# FX engine integration and preserved demonstrations

The editable rack incorporates the runtime repairs from GitHub commit
`c6656685603022193617405c87b831d28f570299` in
`4444J99/audiovisual-media-postproduction-system`.
The integration starts from Site source commit
`957093108309ef1e02df2cbed9b797a346000f4a`.

## Reconciled source

The Site's `core.mjs`, `audio-engine.mjs`, and `workbench-state.mjs` matched
GitHub commit `7ad06f9657a57c1fd162c4e38331f03e1946d758` before integration.
The app added bounded parallel asset loading, progress, retry, and playback
status behavior. Those Site changes are retained while applying both sets of
GitHub review repairs through the current repair commit.

| Area | Result |
| --- | --- |
| Core, audio, visual, workbench state | Exact repaired GitHub module bytes |
| App | Repaired editing behavior plus the Site's bounded loader and status handling |
| Asset loader | Preserved unchanged |
| Cached pictures | Require current producing-code hashes as well as the existing patch signature |
| Offline CLI and exported render records | Maintained in GitHub; no additional offline renderer is introduced here |

The runtime repairs cover graph reachability and output validation, duplicate
cable coalescing on removal, feedback reset crossings, queue overflow timing,
decoded monitor validation, transactional macro edits, authored bypass/solo
state, keyboard undo gestures, output-ID-aware insertion, phase ordering,
picture-region bounds, and exact partial-audio output accounting.

## Original render provenance

The existing factory films, source assets, patches, manifest, and render receipts
are preserved. None was regenerated by this integration. Their six recorded
producing-module hashes match the immutable GitHub revision `7ad06f9657a57c1fd162c4e38331f03e1946d758`;
that matching revision is a route to the recorded source code, while the original
manifest and per-render receipts remain the producing-code evidence.

`public/fx/engine-provenance.json` records the original manifest's SHA-256 and
byte count, its 25 entries, its recorded module hashes, and the current module
hashes. The existing `watch.html` player still plays those films with their own
muxed sound and orientation-specific pictures. Its copy identifies the earlier
engine. Editing the same named patch can now produce a different result where a
processor was repaired.

The editable rack never pairs one of these earlier cached pictures with sound
from the repaired engine. A future rendered set is eligible only when its
manifest records all six current engine hashes, the entry is complete, and its
patch signature matches. The optional preview index retains its independent
eight-second timeout and does not block source readiness.

## Focused verification

Run the dependency-free runtime and loading checks from this checkout:

```sh
node --test tests/fx/*.test.mjs tests/asset-loader.test.mjs
node --check public/fx/app.mjs
```

The runtime tests are copied from the repaired GitHub revision with only the
default module path adapted from `web/fx` to `public/fx`. The GitHub offline CLI
tests remain with that CLI. Additional tests verify current source hashes,
preserved manifest identity, rejection of older/missing engine provenance,
acceptance of a complete matching revision without mutating its evidence, and
compatibility of the existing WAV monitors with the stricter source binding.

These automated checks do not establish browser/device performance or artistic
acceptance. Preserved loading protections do not guarantee smooth live visual
playback on every device. The original films remain available in the separate
demonstration player.

## Repository and Site application alignment

The canonical repository now carries the exact same 19 top-level FX HTML, JavaScript, CSS and provenance files as published Site source `e1632852f8b7cedd1623a36fb314589a7257dafa`. The six previously divergent/missing application files are copied from that verified source: `app.mjs`, `asset-loader.mjs`, `engine-provenance.json`, `index.html`, `preview-provenance.mjs` and `watch.html`. The native offline renderer and shared processing modules remain unchanged.

The full original factory render manifest is preserved as metadata under `projects/god-here/fx/evidence/preserved-factory-render-manifest.json`. It keeps its original hash and does not add media binaries to Git. Four provenance regressions and six loader regressions run under the existing repository FX suite; their source paths are adapted to the repository layout. This closes the loading/preview-policy drift between the two application copies, without reassigning old films to the repaired engine. The [alignment receipt](../../manifests/acceptance/god-here-repository-workbench-fx-alignment.json) lists all exact file identities.
